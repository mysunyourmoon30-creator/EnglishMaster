# v0.3.0 Go-Live Execution Packet

## Status

`Deferred - Use Only When Hosting Is Available`

## Purpose

This packet is the shortest path from the current approved state to a closed v0.3.0 production go-live if production hosting is provided later. It does not replace the full runbook at `docs/deployment/production-vps-deployment.md`; it lists only the information and evidence needed to finish closure.

For the current no-hosting path, use the private/internal local run instructions in `docs/deployment/local-run.md`.

## Required Inputs

| Input | Status | Notes |
| --- | --- | --- |
| VPS public IP | Missing | Required before DNS can be pointed. |
| SSH user and host | Missing | Required to run deployment commands. |
| Web domain | Missing | Example: `app.example.com`. |
| API domain | Missing | Example: `api.example.com`. |
| Production SQL password | Missing | Store only in server `.env`; never commit. |
| Bootstrap SuperAdmin email/password | Missing | Remove after first successful login. |
| SMTP provider decision | Missing | Use SMTP if live email is required; otherwise intentionally launch with `Development` provider. |
| Alert recipient email | Missing | Required for email alerting. |

## Execute On The VPS

1. Install Docker and confirm `docker compose version`.
2. Clone the repository and checkout tag `v0.3.0`.
3. Create a private `.env` next to `docker-compose.production.yml`.
4. Copy `Caddyfile.example` to `Caddyfile` and replace placeholder domains.
5. Run `docker compose -f docker-compose.production.yml up -d --build`.
6. Apply EF Core migrations to the production database.
7. Confirm all containers are healthy.
8. Confirm API ready health and Web live health return `Healthy`.
9. Log in as the bootstrap SuperAdmin.
10. Rotate/remove bootstrap SuperAdmin credentials and restart the API container.

## Evidence To Record

Update these files during execution:

- `docs/release/v0.3.0-production-deployment-record.md`: production URL, revision, timestamps, deployment step results.
- `docs/testing/v0.3.0-production-smoke-test-results.md`: smoke check results.
- `docs/release/v0.3.0-monitoring-execution-record.md`: first 30 minutes, first 4 hours, and first business day monitoring.
- `docs/release/v0.3.0-go-live-closure.md`: mark closure complete only after deployment, smoke, monitoring, and final sign-off.

## Closure Rule

Do not mark v0.3.0 go-live closed until all of the following are true:

- Production deployment is recorded against a real production URL.
- Production smoke test passes.
- First-business-day monitoring is complete.
- Release owner signs off closure after reviewing the production evidence.
