## Optimized Search Results

Applied changes:

- Added SQL Server indexes for active word prefix filtering.
- Added SQL Server full-text catalog/index for word text, slug, Thai meaning, and English meaning.
- Added a fast prefix path for SQL Server searches.
- Added a full-text path using `CONTAINSTABLE` per indexed column so mixed-language full-text columns work reliably.
- Changed search paging to fetch the current page plus one extra row instead of counting every matching row for broad searches.

## Finding

The system can run against a 1,000,000-record SQL Server dataset, and the main quiz admin flow remains responsive.

The original word search path was not production-ready at this volume. The repository search used a contains-style query over text fields, which caused SQL Server to scan a large active word set. At this dataset size, a targeted search for one active word took about 13 seconds.

After optimization, common admin search paths are responsive on the 1,000,000-record dataset. Broad searches now return the visible page quickly and use an approximate total for pagination instead of blocking the UI while counting every matching row.

## Recommendation

For production readiness, keep these rules:

- Run migrations before load testing or go-live so the full-text index exists.
- Wait for full-text population to complete after the first migration on large databases.
- Keep broad search result counts approximate in UI copy, such as "more results available", instead of promising an exact total for very large result sets.
- Keep the load-test database separate from `EnglishMasterInternal`.
