# V1-F05 — Daily Vocabulary Review

You own this feature end to end in the current worktree. Read `AI_RULES.md` and the repository instructions before editing. Follow the `clean-architecture-dotnet`, `efcore-sqlserver`, and `blazor-feature` guidance available under `.agents/skills/`. Do not commit, merge, push, deploy, or edit files outside the task contract.

## Outcome

Extend the existing authenticated Practice module with a learner-facing daily vocabulary view. It should return up to 10 due word practice items by default, enriched with the Word data learners need, and render them as useful review cards at `/learn/vocabulary`.

This task builds on the existing spaced-repetition data. Do not create a second scheduler, a second practice aggregate, a migration, or a new registration path.

## Required API

- Add `GET /api/v1/me/practice/vocabulary/today?limit=10` inside the existing authorized Practice route group.
- Clamp `limit` to 1–20, default 10. A non-numeric query remains standard model-binding failure; do not make an unbounded query.
- Return only active Word-backed practice items owned by the authenticated user that are due at the current time.
- Order deterministically: due time first, then stable tie-breakers. Return each practice item at most once.
- Never return another user's item, inactive words, non-word content, future-due items, or suspended items.
- Keep all EF queries asynchronous, bounded, cancellation-aware, `AsNoTracking`, and projection-oriented. Avoid N+1 queries.

## Learner contract

Add a `DailyVocabularyItemDto` (or equivalently clear name) containing at least:

- practice item ID, word ID, review status, due/next-review time;
- word text, IPA UK, IPA US, Thai reading;
- Thai meaning, English meaning, part of speech, nullable CEFR;
- English example and Thai example.

Map only learner-safe fields. Reuse the existing Practice application/repository boundary and existing registered `IPracticeApiClient`; do not edit either `Program.cs`.

## UI

- Add an interactive page at `/learn/vocabulary` under `Components/Pages/Vocabulary`.
- Show loading, empty, error, and populated states.
- Default to 10 cards. Make the word, pronunciation, Thai/English meanings, part of speech, CEFR, examples, and review timing easy to scan.
- Include a clear CTA to `/learn/practice` for the actual review session. If no items exist, explain that the learner may need to prepare practice items and provide a safe action using the existing practice client if appropriate.
- Use semantic markup, keyboard-accessible controls, accessible status/error text, and a colocated `.razor.css`. Do not touch global CSS, shared navigation, `_Imports.razor`, or frontend `Program.cs`.

## Tests

Extend focused Practice tests to prove:

- unauthenticated requests are rejected;
- the default returns no more than 10 and explicit limits are clamped to 1–20;
- other-user, inactive-word, non-word, future-due, and suspended records are excluded;
- rich Word fields and review metadata are mapped correctly;
- ordering is deterministic and duplicate items are not returned;
- empty results return HTTP 200 with an empty collection.

Prefer realistic repository/integration coverage for ownership and EF projection. Add unit tests only where they materially cover pure logic. Run the task checks in the contract. If a check fails, fix only this feature. Leave the worktree ready for integrator review and summarize changed files, tests, and remaining limitations in your final output.
