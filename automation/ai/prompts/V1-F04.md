## Outcome

Deliver a small, honest learner diagnostic vertical slice that reuses the existing Quiz aggregate and `IQuizRepository`. An authenticated learner can open a published, active quiz by ID, answer it without receiving answer keys, submit once to the server, and receive a score plus a bounded CEFR recommendation.

This is a first diagnostic slice, not a statistically calibrated A1–C2 placement engine. Never claim a precise global level from uncalibrated content. If the quiz has a CEFR label, describe the result as performance at that quiz's band; if it does not, return no assessed CEFR and give neutral guidance.

## Required API

- Add learner-only routes under `/api/v1/me/diagnostics` and require authorization at the route group.
- `GET /quizzes/{quizId:guid}` returns a learner-safe quiz payload.
- `POST /quizzes/{quizId:guid}/submit` accepts only question IDs and selected choice IDs and evaluates them server-side.
- Return 404 for a missing, unpublished, inactive, or unusable quiz. Do not reveal which eligibility check failed.
- Reject malformed submissions with a validation problem: cap collection size, require unique question IDs, require every submitted choice to belong to its submitted question, and do not accept unknown/inactive questions or choices.
- A submission must cover every active question exactly once. Define and test the behavior for a quiz with no active answerable questions.

## Security boundary

- The GET response must never contain `IsCorrect`, answer keys, correctness hints, or explanations that reveal the answer.
- Do not reuse admin quiz contracts or admin query handlers at the HTTP boundary.
- Do not trust scores, CEFR levels, passing thresholds, question text, or correctness supplied by the browser.
- Compute score and pass/fail from the freshly loaded aggregate on the server. Handle the zero-question case without division by zero.
- Do not log submitted answers or personal data. Do not expose exception details.
- Keep authorization on the API; hiding the Blazor page is not authorization.

## Result contract

At minimum return: quiz ID/title, correct count, total questions, integer percentage score, passing score, passed flag, nullable assessed CEFR, and a concise recommendation. The recommendation must distinguish pass/fail and must not overstate placement accuracy.

## Verification

Add focused unit tests for evaluation/validation and integration tests covering:

- unauthenticated requests are rejected;
- published active quiz is learner-safe and inactive content is filtered;
- unpublished/inactive quiz is indistinguishable from missing;
- correct server-side scoring and passing boundary;
- duplicate, incomplete, mismatched, and oversized submissions are rejected;
- no answer key or `isCorrect` field appears in the GET JSON;
- null CEFR and zero-answerable-question behavior.
